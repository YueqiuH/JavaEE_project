# 智慧校园服务平台 - 团队分工说明

## 项目概述

智慧校园服务平台采用前后端分离架构：
- **后端**：Spring Boot 3.5.13 + JDK 25 + MyBatis Plus + Redis + SpringDoc + Spring AI
- **前端**：Vue 3 + Vite + Element Plus + Axios + ECharts
- **数据库**：MySQL（school_spring）
- **包名**：`com.smartcampus`

## 实施优先级

- A1-A5、B1-B5、C1-C5、D1-D5 为必做内容。
- A6、B6、C6、D6 的 AI 功能为加分项，不得阻塞核心项目的构建、启动和验收。
- 架构、接口和协作边界以 [`架构基线.md`](./架构基线.md) 为最高优先级基线。

## 成员 A：教务核心、学业管理与 AI 智能学习助手

> 负责教务处、教师与学生之间最核心的日常教学、选课及成绩流转业务，并引入 AI 辅助学习。

### 模块清单

| 序号 | 系统模块 | 业务闭环说明 |
|------|----------|-------------|
| A1 | **排课与课表管理系统** | 教务人员导入学期课程与教室资源（CRUD），自动/手动排课；学生和教师在线查询各自的日历式课表，支持调课申请与审批流转 |
| A2 | **选课与容量控制系统** | 学生在线选课（我的选课），系统进行库存/冲突校验；教师实时查看选课名单，教务人员根据选课情况动态调整选课名额 |
| A3 | **成绩评定与预警系统** | 教师在线录入/修改期末成绩并提交；系统自动计算绩点，标注不及格情况，并对学分不足的学生自动触发学业预警 |
| A4 | **考试安排与重修补考系统** | 教务发布期末考试与监考安排，教师查询监考任务；学生查询考试时间与座位，不及格学生可在线进行补考或重修报名 |
| A5 | **毕业设计过程管理系统** | 教师发布毕业设计课题，学生在线选题；系统支持中期报告提交、教师在线批注与修改意见反馈 |
| A6 | **AI 智能学习助理** :bulb: | 集成大语言模型，学生可上传课件、大纲，AI 自动生成知识点摘要、复习题，并根据学生的历史成绩和选课情况，自适应推荐学习路径规划 |

### 后端模块

- **Controller 包**：`com.smartcampus.app.controller.teaching`
- **Service 包**：`com.smartcampus.app.service.teaching`
- **涉及表**：course, score, grade, student, classroom, schedule, selection, exam, graduation

## 成员 B：学籍管理、学生事务与 AI 心理预警系统

> 负责学生在校期间的身份变动、日常奖助贷申请、实践活动，以及学生身心健康的监测与辅导。

### 模块清单

| 序号 | 系统模块 | 业务闭环说明 |
|------|----------|-------------|
| B1 | **学籍变动与信息审核系统** | 学生修改个人非核心信息；学生提交休学、复学、转专业等学籍异动申请，辅导员和教务人员进行二级在线审核 |
| B2 | **奖助贷资助与评审系统** | 学生在线提交奖学金、困难补助、生源地助学贷款等申请；辅导员/教师在后台进行名额评定与材料审核，生成资助名单 |
| B3 | **评教反馈与教学质量评估系统** | 学生对授课教师进行在线打分与匿名评教；教师查询个人评教得分，院系负责人可查看本院系整体评教数据 |
| B4 | **学科竞赛与组队系统** | 教师发布竞赛信息与要求，学生在线发起组队、邀请队员、提交报名材料，教师进行队伍资质审核 |
| B5 | **实验室与实践预约系统** | 管理员维护实验室开放时间，学生在线预约实验设备或工位，系统自动校验冲突并发送预约成功通知 |
| B6 | **AI 心理咨询与行为预警助手** :bulb: | 提供 24 小时 AI 心理陪伴对话；同时，AI 分析学生提交的心理测试问卷，对存在潜在高风险的学生向辅导员端发出红橙黄三级行为预警提示 |

### 后端模块

- **Controller 包**：`com.smartcampus.app.controller.student`
- **Service 包**：`com.smartcampus.app.service.student`
- **涉及表**：student, user, scholarship, evaluation, competition, lab, psychology_questionnaire

## 成员 C：协同办公、财务后勤与 AI 辅助审批助手

> 负责教职工的日常协同办公、公文审批、学校资产管理以及学生费用交纳。

### 模块清单

| 序号 | 系统模块 | 业务闭环说明 |
|------|----------|-------------|
| C1 | **学杂费交纳与流水查询系统** | 财务人员导入学费、报考费账单；学生在线支付（学费缴费信息），并支持查询个人一卡通充值、消费近 5 笔历史明细 |
| C2 | **固定资产管理与申领系统** | 教职工提交固定资产（设备、办公用品等）购置或领用申请；部门负责人审批，系统自动更新全校/本部门固定资产台账 |
| C3 | **教职工工作计划与协同系统** | 教职工在线制定个人周/月工作计划；拥有 `work-plan:manage` 权限的负责人可查询、点评全部工作计划，并直接为其他教职工创建指派任务 |
| C4 | **官方公文流转系统（OA）** | 教职工发起公文会签、请示报告或请假申请，从两名指定负责人中选择一人进行单步审批；禁止审批人自审，支持退回发起人修改后重新提交及催办 |
| C5 | **校园会议与通知发布系统** | 会议发起人发布会议通知，选择参会人员；系统自动推送通知，参会人在线反馈"参会/请假"，系统汇总参会情况 |
| C6 | **AI 公文摘要与审批助手** :bulb: | 面对冗长的公文、请示报告，AI 自动提炼核心要点与诉求；在负责人审批时，AI 根据历史审批习惯及学校规章，自动给出"同意/不同意"的推荐理由草稿 |

### 后端模块

- **Controller 包**：`com.smartcampus.app.controller.office`
- **Service 包**：`com.smartcampus.app.service.office`
- **涉及表**：fee, payment, asset, work_plan, document, meeting, notification

## 成员 D：基础数据、信息检索与 AI 智能报表助手

> 负责全校底层的基础信息库维护、校园公共交互板块，以及面向教师/管理人员的数据统计。

### 模块清单

| 序号 | 系统模块 | 业务闭环说明 |
|------|----------|-------------|
| D1 | **教职工与学生信息库（基础CRUD）** | 维护全校教职工和学生的基础数字档案（包含基本信息、职务、职称、所属院系等），支持多条件组合检索与批量导入 |
| D2 | **招生与迎新数据统计系统** | 导入年度招生计划；在迎新期间，实时汇总全校及各院系的新生报到人数、报到率、生源地分布，生成统计图表 |
| D3 | **学生特征多维统计系统** | 统计在校生总量，按院系、专业、班级进行多级穿透展示；统计学生选课偏好及学生生源地分布，为教学规划提供数据支撑 |
| D4 | **院系与专业资源管理系统** | 教务/院系管理员录入并更新各院系介绍、专业设置、培养方案及教研室分布等基础结构数据 |
| D5 | **新闻公告与校园论坛系统** | 管理员发布系统公告、学校新闻；提供校园互动论坛，师生可发布帖子、回复、点赞，管理员可对违规内容进行封禁或删除 |
| D6 | **AI 自然语言报表助手** :bulb: | 教师/管理人员无需手动筛选复杂的表格，只需输入自然语言（例如："帮我统计一下今年计算机专业新生的报到率，并对比去年的数据"），AI 自动查询数据库并生成对应的分析文字与对比图表 |

### 后端模块

- **Controller 包**：`com.smartcampus.app.controller.base`
- **Service 包**：`com.smartcampus.app.service.base`
- **涉及表**：user, student, department, major, enrollment, news, forum_post, forum_comment

## 协作规范

1. **代码风格**：严格参照 `示例/` 目录中参考项目的风格与格式
2. **包结构**：Controller 层按业务模块分包，Service 层同理
3. **接口规范**：统一使用 `/api/v1/<domain>`、`Authorization: Bearer <token>` 和架构基线定义的响应格式
4. **Swagger 文档**：每个接口必须标注 `@Tag` 和 `@Operation` 中文说明
5. **数据库**：所有表建在 `school_spring` 库中，表名小写下划线命名
6. **前端组件**：使用 `<script setup>` 组合式 API，Element Plus 组件库
7. **Git 提交**：每个功能模块独立 commit，commit message 格式：`feat: [模块名] 功能描述`
8. **分支规则**：功能分支从 `develop` 创建并通过 PR 合并；无需他人批准，禁止直接推送 `main` 和 `develop`
